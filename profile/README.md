2) ## Тема проекта:
Фитнес-платформа с игровым персонажем:
> пользователь тренируется — питомец растёт и радуется, пропускает тренировки — грустит и деградирует. Прогресс, планы тренировок, подписка и лёгкие ИИ-рекомендации.

Данные об активности (пульс, шаги) приложение получает через единый API. Источник данных зависит от режима:
- **Тестовый режим** — данные синтетические, генерируются эмулятором.
- **Боевой режим** — данные снимаются с реального устройства: акселерометр и пульсометр на Raspberry Pi.

3) ## Задачи:
- Подключить к Raspberry Pi датчик пульса (MAX30102, I2C) и акселерометр (MPU6050, I2C), реализовать подсчёт шагов по пикам ускорения.
- Реализовать REST/WebSocket API на Pi, отдающий текущие показатели, историю и live-поток.
- Реализовать нативное Android-приложение с экраном тренировок, дашбордом и отображением live-данных.
- Реализовать сервер-мост: хранение истории, авторизация устройств.
- Обеспечить два режима работы API за одним контрактом — тестовый и боевой (см. ниже).

## Компоненты

а) **Android-приложение** — Java, Android SDK, нативная сборка в Android Studio.

б) **Приложение для Raspberry Pi** — Python, FastAPI, RPi.GPIO/smbus2 (I2C). Чтение датчиков, отдача данных по REST/WebSocket.

в) **Сервер-мост** — связывает встраиваемую часть и мобильное приложение: хранение истории показателей, авторизация устройств.

- Backend: Python (FastAPI)
- БД: PostgreSQL
- Клиент: Android (Java, Android SDK)
- ML: обучение в Google Colab, инференс — лёгкая модель на сервере
- Тестовый режим: эмулятор на Python (FastAPI)
- Боевой режим: Raspberry Pi, Python (RPi.GPIO / smbus2, I2C)



---


### Тестовый режим

Эмулятор — обычный сервис на FastAPI, который раз в N секунд генерирует правдоподобные значения пульса и шагов и отдаёт их по тем же путям. Не требует железа, поднимается локально, подходит для разработки и демо.

### Боевой режим

Тот же API, но за ним — Raspberry Pi:

- **Пульс** — датчик MAX30102 (I2C) или аналог.
- **Шаги** — акселерометр MPU6050 (I2C), подсчёт по пикам ускорения.

GPIO/I2C-логика инкапсулирована на стороне Pi и наружу отдаёт данные в том же формате, что и эмулятор. Никакой специфики устройства не просачивается выше уровня API.
